# Reviewer shootout on the M3+M4 cluster -- 2026-09-27

Branch `cluster`. The run was launched from the M3 page (:8899) as a **pipeline split over jaccl**
(the M4 Max 128 GB is rank 0, the M3 Ultra 96 GB is rank 1). Preset `lean` (8-bit KV where the family
takes it, 512-token prompt chunks, MTP off) plus `KNURLOGIC_PROMPT_CONCURRENCY=4`. There were 4 concurrent
reviewer agents with reasoning effort medium, using each model's own sampling defaults. The agents used
read-only tools over `git archive cluster` and went through the page's router. The harness is
`cluster.py` + `agent_core.py` in the scratchpad `shootout/`. Per-area results are in `out-cluster2/<model>/<area>.json`.
Both ranks' logs and a 30 s memory monitor are kept beside them.

The plan changed mid-run: the Qwen3.8-Flash-Next **6bit** run was stopped after 5 of 10 areas.
The model to test is VQ 5.5bpw. GLM-5.3-Flash-4bit was skipped. Every job is stopped, both ranks are
gone, and both :8899 pages are still running.

**Flash-Next 6bit as a reviewer.**
- Strengths: its findings were specific and several held up. It found 4 real bugs in 5 areas:
  - a peer launch port that 500s;

## Cluster bugs hit and fixed (tests first; full suite rc 0 before each commit)

1. `ef4642c`: pipeline placement refused Flash-Next-6bit although it fits.
   - Cause: layer 1 carries a 41.7 GiB embedding, and the split counts layers by the average size.
   - Fix: fall back to a contiguous cut by the real bytes before refusing.
2. `27140a3`: running `pytest` on the M3 killed a real job's rank.
   - Cause: a test starts the watcher thread, which outlives its XDG_CACHE_HOME. It then reads the real `jobs.json` and stops the job after 20 s with no peer page.
   - Reproduced with a decoy rank. Fix: `tests/conftest.py`.
3. `85ecb7d`: a long prefill was judged a stall.
   - One engine step admits a whole prompt, so a 30k-token prompt on the 397B takes more than 2 minutes, and the page tore the job down at 122 s. This happened twice.
   - faulthandler dumps showed both ranks computing.
   - Fix: every prefill chunk bumps the rank's marker, and the watcher reads (step, chunk).
4. `90c22c4`: tool-result turns stored no prompt-cache checkpoint.
   - The prompt was a single "assistant" segment. On hybrid models, every agent turn after the first re-prefilled the whole conversation (397B agents at 15-22k tokens reused 881 tokens).
   - After the fix, per-turn reuse is nearly the whole prefix (the http agent: 30868 of 31161, and so on).
5. `bd82e4e`: a request that arrived during a slow load (137 GiB over SMB) was judged a stall at step 0 and the job was killed mid-load.
   - Fix: the stall clock runs only in phase `ready`.

### Not fixed in knurlogic

- **RDMA on the 10.0.0.x Thunderbolt cable fails QP RTR (errno 96) since the M3 reboot.** A bare 2-rank mlx jaccl all_sum reproduces it, while 10.0.1.x works.
  - knurlogic always picks the lowest shared subnet.
  - Workaround (harness-side, not committed): the M3 page runs via `page_prefer_cable.py`, which pins jaccl to 10.0.1.
  - Follow-up: let a launch name the cable, or retry on the next RDMA subnet when init fails RTR.
- **Prompt-cache eviction under 4 agents:** the count cap of 10 entries (now 3 checkpoints per turn) occasionally dropped an agent back to 833 cached tokens. Worth sizing by bytes or raising for multi-agent use.

## Triage fixes (`f153943`, `1f46423`, `c0af50d`)

- A forwarded load's non-numeric port is refused instead of returning 500.
- A `--peer` given by hostname is trusted at the addresses it resolves to.
- `check_snapshot_semantics` handles `battn` / `attn-list` caches.
- The locked request counter.
